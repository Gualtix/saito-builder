Platform overview

Saito Builder

A configuration-driven, multi-tenant static website factory.

Each site is a YAML file over a versioned template. One Astro renderer turns every site into static HTML for a CDN.

Each section zooms in one level

A site is a YAML file over a versioned template

Many sites, one renderer. Sites only describe what differs from their template, so a template fix reaches every site that pins it.

Precedencetemplate < site config < content overlay
Versioningsites pin a major, e.g. landing@1
Outputstatic files only, served from a CDN

Where things live

A site is a folder under sites/. Build output lands in dist/, which git ignores.

Creating a new website from a template

Site id must equal its directory name. Ids, tenants and section ids are kebab-case.

Adding a new template

defineTemplate validates the manifest when it loads, so a broken template fails before any site uses it.

Adding a section type touches four places

The component map is typed Record<SectionType, …>, so a missing component is a compile error, not a runtime surprise.

Modifying a template: is the change breaking?

Sites pin a major. Non-breaking changes reach every pinned site on its next build. Breaking changes ship as a new major with a migration.

Moving a site to the new major

saito upgrade runs the migration and validates the result before writing anything.

Watch outYAML comments are lost when overrides change. Review the diff before merging.
Migration shapeTemplateMigration: from, to, notes, migrate(config)

Content publishing: from Sanity to the CDN

An editor's publish rebuilds and redeploys exactly one site.

Two directions that must stay exact inverses

saito seed pushes local content and images into Sanity. Builds pull it back as an overlay.

Seedingneeds SANITY_WRITE_TOKEN. Supports --dry-run and --overwrite.
Deploysread Sanity only when the GitHub variable SAITO_CONTENT_SOURCE is sanity.
Document idsmust not contain . (dotted ids are private).

CI on every pull request and push

One verify job, then a build per affected site. A docs-only change builds nothing.

Which sites a change rebuilds

git diff --name-only main | npm run saito -- affected --json applies these rules to each changed file.

Platform codeAnything else counts, including scripts/ and live-sketching/ HTML.
Keep in syncPath rules live in packages/cli/src/commands.ts. Update them if directories move.

Deployment, part 1: three triggers, one plan

Each trigger decides the environment and the list of sites. The plan job turns that into a matrix.

Deployment, part 2: one script, several hosts

Each matrix job builds its site, then scripts/deploy.sh uploads it to the host chosen by DEPLOY_PROVIDER.

Environments, from laptop to production

Each environment has its own URL and Sanity dataset. Non-production builds are always noindex: meta robots, robots.txt and the X-Robots-Tag header.

The life of a site

Minor template releases reach production on the next build. A new major marks the site outdated until it is upgraded.

Side tool: prototype previews on GitHub Pages

live-sketching/ is a standalone workspace for single-file HTML prototypes. It has no code link to the platform; only the publish script is shared.

Security boundaries on the way to HTML

Every value from configuration passes a guard before it is written into a page.

IndexingNon-production builds are always noindex.
SecretsNever in site configs. CI credentials are GitHub environment secrets.
Forms APIPer-site origin allow-list, honeypot, redirects only to the site's own domain.

Gotchas worth knowing on day one

Studio is separateapps/studio is deliberately not an npm workspace: cd apps/studio then npm install
Version pinsRoot overrides pins Vite 6 so Astro 5 and Vitest share one Vite. Stay on Astro 5, Vitest 3, Zod 3, TypeScript 5.
Type checkingpackages/components is checked by astro check through the renderer, not by the root tsconfig.json.
No compile stepPackage exports point at src/*.ts. TypeScript runs through tsx and Vite.
Build through the CLIIt resolves first (clear errors), then runs Astro, then writes the edge artifacts.
No linterNone is configured. Tests and npm run typecheck are the gate.
